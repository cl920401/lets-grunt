# Project review log template

Use the existing authorized evidence record if it fits; otherwise use this template for an authorized `docs/REVIEW_LOG.md`. Do not create a duplicate. Link each row from the relevant step/module status without copying the finding. Plan and standalone Review return a note in chat; only the authorized coordinating writer persists it later.

Use one row per actual event. Record the actor’s role and verifiable non-secret identifier and link the actual confirmation, reviewer response or retained trace, not a summary offered as proof. Separate self-check, independent pre-review, formal confirmation and independent QA. PASS, FAIL and BLOCKED are type-specific: an approved confirmation is not a passed test. For no run, mark BLOCKED, identify the missing evidence, and leave reviewer or trace absent rather than inventing them. Link superseded rows when scopes or versions change.
