# Isolated replay guide

Begin in a fresh disposable project with a single everyday request such as “Can you help me keep this moving?” Explicitly invoke the beta when testing selection or invocation. Supply only the raw fixture artifacts the operator could see. Leave acceptance criteria and expected results with the evaluator. Record an intervention if you later supply missing workflow instructions or a checklist. Score that run as assisted.

| Raw fixture situation | What to inspect |
| --- | --- |
| Goal is underspecified, a minor reversible detail is missing and a material decision is open | The assistant asks the key question, states a reversible default and advances only independent authorized work. |
| A worker says it sent a review, but the destination has no visible receipt yet | The assistant checks the intended session and revision before retrying. It records uncertain delivery and blocks duplicate dispatch if the host cannot resolve it. |
| The candidate changed. Review passed on the older whole and on a patch for the new candidate | The affected gate stays blocked until an eligible independent reviewer passes the whole applicable artifact on the new version. |
| An eligible agent confirmed an ordinary step, and Spec #9 is also awaiting confirmation | The assistant records the ordinary confirmation under the agent's own identity and scope. The verified initiator still confirms the exact Spec outcome. |
| Revisions keep failing because the document contains implementation detail for a later step | The assistant moves out-of-stage detail out of the current deliverable and retains material product and data-safety checks. |
| A same-version smoke test passed and a sandbox refused a write | The assistant reports both observations and leaves final product acceptance and real write-back unverified. |
| Authorization-mode step completed and a later mode looks ready | The assistant reports verified progress and stops at the required human re-entry or explicit mode selection. |

For each host, check discovery and explicit invocation separately. Record host version, exact candidate, fixture, observed behavior, intervention, and native proof or reason it was unavailable. Compare experience, recovery and proof quality. Speed is diagnostic only.

- Codex is the base bundle's target. Verify discovery, explicit invocation policy and any independent-agent trace in the actual client version before relying on it.
- For OpenCode, use the loader and session evidence actually available in the installed build. Do not infer support for Codex UI metadata or confirmation tools from readable skill files.
- For DSH, verify the destination session and its observable dispatch or review receipt in that deployment. Without a verifiable receipt, report delivery as unverified.

Record schema checks, discovery, scenario replays and live operations separately. Keep unrun cases explicit. Use synthetic artifacts and receipts. Never publish credentials, original session content or machine paths.
